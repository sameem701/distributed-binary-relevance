# Milestone 2 Run Instructions

This guide explains how to run `milestone2.ipynb` on another PC.

## 1. Prerequisites: Milestone 1 Must Be Run First

Milestone 2 depends entirely on the output files generated by Milestone 1.
Before running `milestone2.ipynb`, you must have already run `milestone1.ipynb`
successfully and have the following files in your project folder:

- `X_train_normalized.npz`
- `X_test_normalized.npz`
- `train_meta.csv`
- `test_meta.csv`
- `normalization_params.pkl`
- `partition_metadata.pkl`
- `partitions/partition_0.npz`
- `partitions/partition_1.npz`
- `partitions/partition_2.npz`
- `partitions/partition_3.npz`

If any of these are missing, run Milestone 1 first using its run instructions.

> **Note:** Earlier versions of this project used `eurlex_normalized.csv`,
> `eurlex_test_normalized.csv`, and `partitions/partition_0.csv` to `partition_3.csv`.
> Those CSV files are no longer produced. Milestone 2 now reads the `.npz` sparse
> matrix files listed above. Do not look for the CSV versions.

## 2. Required Software

- Python 3.10+ (recommended)
- VS Code with Jupyter extension (recommended) or Jupyter Notebook/Lab
- A running Dask cluster (scheduler + workers) — see Section 6 below

## 3. Required Python Libraries

Install the libraries below in your environment:

- pandas
- numpy
- scipy
- scikit-learn
- dask[distributed]
- matplotlib
- jupyter
- ipykernel

## 4. Setup Commands (Windows CMD)

From the project folder (you can reuse the same `venv` from Milestone 1 if it still
exists):

```bat
python -m venv venv
venv\Scripts\activate
python -m pip install --upgrade pip
pip install pandas numpy scipy scikit-learn "dask[distributed]" matplotlib jupyter ipykernel
```

If you already have the Milestone 1 environment active, just add the new libraries:

```bat
venv\Scripts\activate
pip install scikit-learn matplotlib
```

## 5. File Layout Expected

Your folder should contain at least:

- `milestone2.ipynb`
- `X_train_normalized.npz`
- `X_test_normalized.npz`
- `train_meta.csv`
- `test_meta.csv`
- `normalization_params.pkl`
- `partition_metadata.pkl`
- `partitions/` (folder with 4 `.npz` partition files)

## 6. Starting the Dask Cluster (Multi-Machine)

Milestone 2 connects to a real multi-machine Dask cluster. All machines must be on
the same network (LAN or Wi-Fi) and have the project dependencies installed.

**On the scheduler machine**, run:

```bat
venv\Scripts\activate
dask scheduler
```

The scheduler will print its address, for example:
```
Scheduler at: tcp://192.168.0.103:8786
```

**On each worker machine**, run:

```bat
venv\Scripts\activate
dask worker tcp://<SCHEDULER_IP>:8786
```

Replace `<SCHEDULER_IP>` with the actual IP printed by the scheduler.

**Before running the notebook**, open `milestone2.ipynb` and update the scheduler IP
in the cluster connection cell:

```python
SCHEDULER_IP = "192.168.0.103"   # <-- set this to your scheduler machine's actual IP
```

Worker machines do not need their own copy of the dataset or partition files — the
master (notebook) machine loads all data locally and scatters it to workers over
the network using `client.scatter(..., broadcast=True)`.

## 7. How To Run

1. Start the Dask scheduler and all worker machines as described in Section 6.
2. Open `milestone2.ipynb`.
3. Update `SCHEDULER_IP` to your scheduler's IP address.
4. Select the Python kernel from your `venv`.
5. Run all cells from top to bottom in order.
6. Do not skip any cells — each cell depends on variables defined in the ones before it.

## 8. What Gets Generated

After successful execution, the notebook generates:

- `output_label_distribution.png`
- `models_node_level/node_0/` to `models_node_level/node_3/` (one folder per worker node)
- `models_node_level/node_X/label_Y_model.pkl` (one per trained label per node)
- `models_node_level/node_X/label_Y_coef.npy` (model coefficients)
- `models_node_level/node_X/label_Y_intercept.npy` (model intercept)
- `models_node_level/node_X/node_metrics.csv` (per-node label-level metrics)
- `models_node_level/node_training_summary.csv`
- `models_node_level/all_node_metrics.csv`
- `models_node_level/training_manifest.json`
- `models_node_level/model_registry.csv`

## 9. Expected Runtime

Two cells in this notebook take significant time:

- **Label matrix construction cell** (building `Y_full`): approximately 5–15 minutes
  depending on machine speed. This cell builds a binary target column for every
  unique output label in the dataset (~3,956 labels).
- **Distributed training cell** (Dask workers): approximately 30 minutes to a few
  hours depending on available CPU cores and RAM across all worker machines. This cell
  trains one Logistic Regression classifier per label distributed across 4 parallel
  Dask workers (~989 labels per worker). This is the heaviest cell in the notebook
  and is expected to take long — it is doing the actual work of the milestone.

All other cells complete in seconds.

## 10. Important Note About Distributed Execution

Milestone 2 uses a real multi-machine Dask cluster.

- The notebook machine acts as the master: it loads data, assembles the full feature
  matrix from partition shards, and scatters training and validation data to workers.
- Each worker machine receives its assigned batch of output labels and trains one
  Logistic Regression classifier per label independently.
- Trained model weights are serialized in memory on the worker and returned to the
  master over the network. The master then saves them to disk locally.
- This is the full distributed architecture described in the project design — not a
  LocalCluster simulation.

## 11. Typical Constraints On Other PCs

To run reliably on another machine:

- Have at least 8 GB of free RAM on the master machine (16 GB recommended). The full
  feature matrix (15,377 rows × 5,000 features) and label matrix (~3,956 labels) are
  both held in memory simultaneously.
- Have at least 4 GB of free RAM on each worker machine to receive scattered data and
  run classifier training.
- Have at least 5 GB of free disk space for generated model files and CSVs.
- Keep all Milestone 1 output files in the same folder as `milestone2.ipynb`.
- Ensure all machines on the cluster have the required Python libraries installed.
- Ensure firewalls on all machines allow TCP traffic on port 8786 (scheduler) and
  8787 (Dask dashboard).
- Run cells in sequence without skipping dependencies.
- Do not interrupt the distributed training cell mid-run — if interrupted, restart
  the kernel and re-run from the top.

## 12. Troubleshooting

- If `ModuleNotFoundError` appears, reinstall missing packages in the same environment.
- If `RuntimeError: No active workers` appears, make sure at least one `dask worker`
  process is running and has successfully registered with the scheduler before running
  the connection cell.
- If the connection cell hangs or times out, double-check that `SCHEDULER_IP` is set
  correctly and that port 8786 is not blocked by a firewall on the scheduler machine.
- If `FileNotFoundError` appears for `.npz` or partition files, verify Milestone 1 was
  run successfully and all output files are present.
- If the label matrix cell runs for more than 30 minutes, your machine may not have
  enough RAM. Try closing other applications to free memory.
- If a worker raises a memory error during training, verify the worker machine has at
  least 4 GB of free RAM. If not, reduce the number of labels per worker by increasing
  `num_nodes` in the label batch split.
