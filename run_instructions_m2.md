# Milestone 2 Run Instructions

This guide explains how to run `milestone2.ipynb` on another PC.

## 1. Prerequisites: Milestone 1 Must Be Run First

Milestone 2 depends entirely on the output files generated by Milestone 1.
Before running `milestone2.ipynb`, you must have already run `milestone1.ipynb`
successfully and have the following files in your project folder:

- `eurlex_normalized.csv`
- `eurlex_test_normalized.csv`
- `normalization_params.pkl`
- `partition_metadata.pkl`
- `partitions/partition_0.csv`
- `partitions/partition_1.csv`
- `partitions/partition_2.csv`
- `partitions/partition_3.csv`

If any of these are missing, run Milestone 1 first using its run instructions.

## 2. Required Software

- Python 3.10+ (recommended)
- VS Code with Jupyter extension (recommended) or Jupyter Notebook/Lab

## 3. Required Python Libraries

Install the libraries below in your environment:

- pandas
- numpy
- scikit-learn
- dask[distributed]
- matplotlib
- jupyter
- ipykernel

## 4. Setup Commands (Windows CMD)

From the project folder (you can reuse the same `venv` from Milestone 1 if it still exists):

```bat
python -m venv venv
venv\Scripts\activate
python -m pip install --upgrade pip
pip install pandas numpy scikit-learn "dask[distributed]" matplotlib jupyter ipykernel
```

If you already have the Milestone 1 environment active, just add the new libraries:

```bat
venv\Scripts\activate
pip install scikit-learn matplotlib
```

## 5. File Layout Expected

Your folder should contain at least:

- `milestone2.ipynb`
- `eurlex_normalized.csv`
- `eurlex_test_normalized.csv`
- `normalization_params.pkl`
- `partition_metadata.pkl`
- `partitions/` (folder with 4 partition CSV files)

## 6. How To Run

1. Open `milestone2.ipynb`.
2. Select the Python kernel from your `venv`.
3. Run all cells from top to bottom in order.
4. Do not skip any cells — each cell depends on variables defined in the ones before it.

## 7. What Gets Generated

After successful execution, the notebook generates:

- `output_label_distribution.png`
- `models_node_level/node_0/` to `models_node_level/node_3/` (one folder per worker node)
- `models_node_level/node_X/label_Y_model.pkl` (one per trained label per node)
- `models_node_level/node_X/label_Y_coef.npy` (model coefficients)
- `models_node_level/node_X/label_Y_intercept.npy` (model intercept)
- `models_node_level/node_X/node_metrics.csv` (per-node label-level metrics)
- `models_node_level/node_training_summary.csv`
- `models_node_level/all_node_metrics.csv`
- `models_node_level/training_manifest.json`
- `models_node_level/model_registry.csv`

## 8. Expected Runtime

Two cells in this notebook take significant time:

- **Label matrix construction cell** (building `Y_full`): approximately 5–15 minutes
  depending on machine speed. This cell builds a binary target column for every
  unique output label in the dataset (~3,956 labels).
- **Distributed training cell** (Dask workers): approximately 30 minutes to a few
  hours depending on available CPU cores and RAM. This cell trains one Logistic
  Regression classifier per label across 4 parallel Dask workers (~989 labels per
  worker). This is the heaviest cell in the notebook and is expected to take long —
  it is doing the actual work of the milestone.

All other cells complete in seconds.

## 9. Important Note About Distributed Execution

Current implementation uses a Dask `LocalCluster`.

- It runs 4 Dask workers in parallel as separate processes on a single PC.
- It is a local simulation of distributed processing.
- It is not a true multi-machine cluster in the current state.

## 10. Typical Constraints On Other PCs

To run reliably on another machine:

- Have at least 8 GB of free RAM (16 GB recommended). The full feature matrix
  (15,377 rows × 5,000 features) and label matrix (~3,956 labels) are both held
  in memory simultaneously.
- Have at least 5 GB of free disk space for generated model files and CSVs.
- Keep all Milestone 1 output files in the same folder as `milestone2.ipynb`.
- Run cells in sequence without skipping dependencies.
- Do not interrupt the distributed training cell mid-run — if interrupted, restart
  the kernel and re-run from the top.

## 11. Troubleshooting

- If `ModuleNotFoundError` appears, reinstall missing packages in the same environment.
- If Dask worker startup fails, close old Python/Jupyter processes and try again.
- If `FileNotFoundError` appears for normalized CSV or partition files, verify
  Milestone 1 was run successfully and all output files are present.
- If the label matrix cell runs for more than 30 minutes, your machine may not have
  enough RAM. Try closing other applications to free memory.
- If a worker raises a memory error during training, reduce `n_workers` in the
  `LocalCluster` call from 4 to 2.

## 12. Future Multi-Machine Upgrade Note

This project will later be upgraded from `LocalCluster` to a multi-machine Dask
cluster (as it requires separate machines to be on the same network, which was not
feasible during development). This run guide will need to be updated at that point.

Probable changes:

- A scheduler process would run on one machine and workers would run on other machines.
- All machines would need network reachability (same LAN/Wi-Fi, VPN, or other reachable network).
- Firewalls and ports would need to allow scheduler/worker communication.
- Data paths (normalized CSVs, partition files) would need to be shared or
  synchronized across machines before training begins.
- The `LocalCluster` and `Client(cluster)` lines in the notebook would be replaced
  with `Client("<scheduler-ip>:8786")`.
- Cluster startup commands would be different from local-only startup.

Current notebook is configured for single-machine execution using `LocalCluster`,
so these distributed infrastructure steps are not required right now.
